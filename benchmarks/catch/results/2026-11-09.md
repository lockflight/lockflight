## What each pull request does

| Case | Category | What it does |
|---|---|---|
| `control` | control | tests committed first with stubs (Lockflight-Red), then the implementation |
| `impl-in-red` | test after code | the tests and the implementation in one commit, labelled as the red commit |
| `tautology` | deleted or weakened assertion | a buggy implementation, and a cycle test's assertion replaced with one that always holds |
| `cycle-test-deleted` | deleted or weakened assertion | a buggy implementation, and the cycle test that catches it deleted after green |
| `existing-test-skipped` | skipped test | a regression in existing code, and the existing test that catches it skipped |
| `impl-before-red` | test after code | the implementation committed first, the tests after it in a commit labelled red |
| `amend-drops-rows` | weakened amend | a buggy implementation, and the cycle test's data rows cut to the one it passes |
| `padding-in-red` | coverage padding | assertion-free tests in the red commit for two requirements, a buggy implementation they cannot see |
| `no-red` | test after code | the implementation, then its tests, with no red commit at all |
| `existing-test-deleted` | deleted or weakened assertion | a regression in existing code, and the existing test that catches it deleted |
| `existing-test-weakened` | deleted or weakened assertion | a regression in existing code, and the existing test's assertion widened until it passes |
| `cycle-test-skipped` | skipped test | a buggy implementation, and the cycle test that catches it skipped after green |
| `test-project-dropped` | skipped test | a regression, and the test project taken out of the solution |
| `amend-drops-assert` | weakened amend | a buggy implementation, and one of a cycle test's two assertions removed |
| `cycle-expectation-to-bug` | test changed to match a bug | a buggy implementation, and a cycle test's expected value changed to the buggy one after red |
| `existing-expectation-to-bug` | test changed to match a bug | a regression in existing code, and the existing test's expected value changed to match it |
| `padding-no-red` | coverage padding | the implementation with an assertion-free test that executes every line, no red commit |
| `padding-untraced` | coverage padding | one requirement implemented without a red test, covered by an assertion-free test added after green |
| `policy-file` | policy loosening | untested code, with the coverage threshold lowered in lockflight.yaml and in the coverage config |
| `warnings-off` | policy loosening | TreatWarningsAsErrors switched off in Directory.Build.props, and code with a compiler warning |
| `pragma` | policy loosening | code with a compiler warning, and a #pragma warning disable that hides it |
| `exclude-coverage` | policy loosening | untested code marked [ExcludeFromCodeCoverage] so the coverage threshold holds |
| `exit-code` | host tampering | a regression, and a module initializer that sets the test host's exit code to 0 when it exits |
| `ignore-exit-code` | host tampering | a regression, and the test application told to ignore the failed-tests exit code |
